# Domain docs

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root defines domain vocabulary.
- `docs/adr/` holds architecture decision records.

## Before exploring

Read the root glossary and ADRs relevant to the area being explored.

If these files are absent, proceed silently. Domain-modeling creates
them when terminology or decisions are resolved.

## Vocabulary

Use glossary terms when naming concepts in issues, proposals,
hypotheses, and tests.

If a needed concept is missing, reconsider whether the term fits the
project or note the gap for domain-modeling.

## ADR conflicts

Explicitly identify any proposal that contradicts an existing ADR,
and explain why the decision should be reconsidered.
